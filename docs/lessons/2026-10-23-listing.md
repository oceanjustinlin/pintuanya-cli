# 商品上架流程复盘：2026-10-23

## 存放方式

这次经验主要依赖本项目的 CLI、拼团呀协议及本机登录方式。用项目内的 `AGENTS.md` 保存执行规则，本文保存原因与证据，`docs/catalog.md` 保存具体命令。暂不创建全局 memory 或 skill，以免把特定店铺、设备及临时接口信息泛化到其他任务。

具体商品状态放在本地 Git 忽略的 `HANDOFF.md` 和 `plans/`。不在本复盘记录 Cookie、上传 token、商品 UUID、经营数据或临时 IP。

## 错误与修正

| 错误 | 原因与证据 | 今后的处理 |
| --- | --- | --- |
| 未先确认用户操作偏好就转向网页 | CLI 没有直接封装某些动作，便把 UI 当作下一步；用户明确要求 CLI | 本项目默认 CLI；缺封装时检查已有实现并补齐，不自行切网页 |
| 把“主 CLI 无创建子命令”说成“无法用 CLI 创建” | 只检查 `--help` 和仓库主文件；用户引用的另一聊天实际用临时 Python/curl 脚本调用创建接口成功 | 分开说明已封装命令、已验证接口和当前缺项；读取用户提供的聊天后再下结论 |
| 商品结构理解错，建立了两个独立商品 | 按用户最初“两个 SPU”的字面含义执行；后来用户明确是一个商品两个规格 | 写入前核对商品数和规格数；术语与业务描述存在歧义时只确认这一点，不凭颜色图数量推断商品数量 |
| 多次要求重复制 Cookie | 最初只依赖环境变量或剪贴板，未提供已获授权的持久登录 | 用户明确授权后保存到本机钥匙串；之后自动读取，失效时才更新 |
| 将读取失败或非文本误报为空剪贴板 | 有的 `pbpaste` 调用退出非零；另一次原生接口确认剪贴板只有 PNG/TIFF | 先看退出码，再看是否有文本；需要诊断时只输出格式和长度，不输出凭据 |
| 将连接错误当成登录问题 | 观察到了 TLS 中断、Python 信任链差异和代理虚拟 DNS 地址 | 先分离 DNS、TLS、HTTP、业务登录四层；只有后台明确拒绝登录才判断会话过期 |
| 置顶请求直接提交字符串 TOP | 只看了界面枚举和服务函数，漏掉中间点击处理器将 TOP 转成数字 3 | 查看完整调用链，保存业务枚举到接口值的转换，并用回归测试约束 |
| 上传返回 null 导致程序报错 | 七牛上传已完成，但回调 JSON 为 null；网页随后检查审核状态 | 不假设回调总有 key；核对返回标识（若存在）和后台审核结果；重试前按摘要去重回查 |
| 把离线测试通过当成可交付线上能力 | 协议映射和回调形态的问题都在实测时暴露 | 离线验证保护代码；线上验证保护实际结果，最终报告区分两者 |

“空剪贴板”并非单一根因：这次既出现过受限进程读取失败，也出现过剪贴板确实为图片。不能把所有失败归为权限问题，也不能归咎于用户没复制。

## 建议执行顺序

1. 读取项目约定和功能目录。确定商品数、规格数、逐规格价格/图片/库存、分类和排序要求。
2. 优先环境变量，其次本机钥匙串。缺少登录信息时再获取一次，并在授权范围内持久保存；不以剪贴板作为长期依赖。
3. 做最小只读登录和分类检查。网络失败先排网络，业务登录失败再更新会话。
4. 上传图片，按摘要去重并等待审核；取审核通过的短 HTTPS 地址。
5. 在目标分类完整分页检查已有商品。新建后的搜索可能漏项，不能只凭搜索结果决定重复创建。
6. 生成并核对计划。一个商品多规格用 `variants`，不生成多个独立 create 对象。
7. 执行创建，保留 sending/done 状态。请求结果不确定时只续跑回查，不再 POST。
8. 创建回查通过后单独执行排序。核对最终分类位置，而非只看接口“成功”。
9. 报告实际商品和规格结果。记录当前状态到本地交接文件，通用新发现回写代码、测试及文档。

## 纠正误建的方法

保留一个商品原位增加两个规格，保留原 SKU 标识；新规格使用新的 SKU，不把另一商品的 SKU 标识跨商品挪用。修改前核对销售状态并保存快照。合并后回查规格、价格和图片，再下架多建商品；不默认永久删除。

涉及在售或已售记录时，不按“新商品应该没人买”假设执行。发现状态变化要停止并核对，避免覆盖订单关联和库存变化。

## 这次已落实的防护

- CLI 补充商品创建、多规格、分类、绝对排序、图片上传和钥匙串登录。
- 计划摘要、发送前状态记录、回查及不重复创建逻辑。
- 排序协议数字转换、上传 null 回调处理、分页完整性检查。
- 可选系统 curl 传输，保留证书验证、禁用默认 curl 配置，不把 Cookie 放在 argv。
- 登录凭据只经环境变量或钥匙串读取；保存时通过标准输入传递。
- 测试覆盖凭据传递、上传回调、规格校验、排序协议和中断续跑；线上操作另行回查。

## 仍然存在的限制

这些是后续改进项，不应写成已经解决：

- 当前误建合并使用了专用修正脚本。通用的“修改商品及规格”计划命令仍未封装；`catalog-plan` 支持多规格创建，不代表支持通用合并。
- 钥匙串写入依赖本机 Swift 工具链，属于 macOS 功能。
- 仅支持单进程执行同一计划；当前没有进程间互斥锁。
- 后台协议可能变化。不要把临时 DNS IP、单次成功响应或历史快照当作长期事实。
