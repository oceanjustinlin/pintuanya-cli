# CLI 登录与统一凭据方案

状态：用户已批准并实现；离线测试与线上只读、二维码获取/轮询/超时检查通过。2026-11-01 已通过真实扫码确认、回调取 Cookie 和保存后独立新进程验证。本文不含登录凭据。

## 目标与范围

用户不再需要用 F12 复制 Cookie。CLI 提供微信扫码登录并自动保存登录结果；运行时统一通过环境变量读取凭据，取消系统钥匙串兜底。默认用项目根目录 Git 忽略的 `.env` 持久保存 Cookie 和设备 ID。不能承诺延长后端会话有效期。

## 已核实的依据（2026-11-01，均通过命令行）

- 改造前 CLI 只读取环境变量或钥匙串，既不自动加载 `.env`，也不处理响应中的 Set-Cookie。
- 加载现有 `.env` 后，只读拼团列表请求成功；该次请求没有返回 Set-Cookie。不能据此确定会话时长、滑动续期或失效原因。
- 拼团呀公开前端使用 `GET /api/v1/wx/login-params`，返回 appid、redirect_uri、state；实际回调位于 `https://www.pintuanya.com/auth`。
- 带前端请求头访问登录参数接口成功；微信 qrconnect 页面包含二维码路径和扫码轮询入口。页面逻辑在确认扫码后使用 code 和 state 跳转回调。
- 初次调研时未实测用户扫码、回调设置 Cookie、登录持久化后的真实请求；2026-11-01 已完成这些线上验收，见下方记录。

## 两种环境变量使用方式

推荐本地默认使用 `.env`：CLI 启动时加载到进程环境，auth-login 更新同一文件，后续命令直接使用；无需修改父终端变量。

自动化环境可显式使用 `--no-env-file`，只接收外部注入的变量。这种模式不保存新 Cookie，也不向 stdout 输出 Cookie；auth-login 应明确拒绝该模式并说明需要可写配置文件。

## 配置规则

- 默认配置定位到脚本目录的 `.env`，不随工作目录变化。可用全局 `--env-file PATH` 显式选择其他配置文件；与 `--no-env-file` 互斥。
- 本地文件存在时，以文件中的凭据对为准，不把外部 Cookie 和文件设备 ID 混用，也不回退到钥匙串。缺少 Cookie 时明确提示 auth-login；缺少设备 ID 时由 auth-login 生成并持久保存，导入已有 Cookie 时同样固定设备 ID。
- 其他非凭据配置沿用外部环境优先、文件补缺的规则。加载发生在读取参数默认值之前，使 PINTUANYA_GROUP 等字段也生效。
- 默认文件不存在时，可读取外部环境变量；status 清楚标记来源。外部来源缺少设备 ID 时提示绑定稳定设备 ID，不把它认定为当前 Cookie 失效的已证实原因。
- 解析 `.env` 采用明确的键值、引号、注释语法，不执行 shell，不执行变量展开或命令替换；格式错误只报告行号，不回显原行。
- 保存权限为 0600；使用同目录临时文件原子替换，保留其他配置和注释，拒绝符号链接目标。验证失败、超时、中断不覆盖现有凭据。保存前确认文件没有被其他进程修改，冲突时停止。

## 命令与体验

### auth-login

1. 使用稳定设备 ID 获取登录参数；临时 state 与会话上下文只保留在内存。
2. 通过 CLI 获取微信二维码并保存到权限受限的临时 PNG/JPEG，打印本地文件位置；提供 `--qr-output PATH` 指定位置。不会自动打开浏览器。二维码在结束时默认清理，显式输出的文件提示用户其临时性质。
3. 按微信页面协议轮询，区分等待扫码、已扫码待确认、取消、过期与确认成功。设置总超时和合理请求间隔，Ctrl-C 可取消，不无限请求。
4. 确认后通过 HTTP 完成实际回调，收集适用的 Set-Cookie。回调只使用本次参数中的 state，并沿用同一登录会话的 Cookie 上下文，拒绝回调 URL 预置冲突 code/state；不使用 eval 解析微信脚本。只向原站发送原站 Cookie；回调及跳转须匹配已核实的 HTTPS 主机与路径范围。
5. 使用新 Cookie 和同一设备 ID 执行只读登录检查；通过后原子更新 `.env`，只输出成功状态及配置路径。
6. 若回调要求额外交互或无法完成，明确报告未完成，不伪装成功、不覆盖旧配置，也不绕过用户的禁用浏览器约束。

### auth-status

显示配置路径、凭据来源、Cookie/设备 ID 是否存在，并执行只读登录检查。区分缺配置、网络/TLS/HTTP 错误与明确的业务登录失效。不显示 Cookie、OAuth 临时参数或未经证实的过期倒计时。

现有 check 保持兼容。原 auth-save 改为校验后保存到 `.env`，保留标准输入和剪贴板导入作为人工备用通道；不再存钥匙串，也不主动删除原钥匙串条目。

## 会话及错误处理

- 若原站实际响应返回新 Cookie，在验证域、路径和失效属性后合并到当前会话；仅在对应凭据仍未被其他进程替换且配置来源可写时保存。不能把支持 Set-Cookie 等同于后端保证续期。
- urllib 和 curl 统一识别 HTTP 401/403 与业务登录失效，保留退出码 2；网络问题不能冒充 Cookie 过期。
- Cookie、OAuth code/state、二维码会话标识和响应中的令牌不进入日志、异常、命令参数或计划；带敏感查询串的请求通过标准输入传给 curl。
- 不在商品写请求中自动扫码或自动重发写请求。会话失效即停止，用户登录后使用已有的回查与 resume 流程，避免重复写入。
