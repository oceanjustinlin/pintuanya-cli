# 订单查询与导出方案

状态：已实现（`orders`、`orders-export`）。离线测试通过；2026-11-03 对真实拼团做了只读验收。用户确认的需求：主要用于对账统计，个人信息默认脱敏。使用说明和接口依据见 [订单查询与导出](../../orders.md)。本文不含登录凭据和订单数据。

## 范围

- 只读：订单列表查询、CSV 导出。发货、退款等写操作不在本期范围；以后如需实现，沿用 `plan` → `apply`：生成计划，执行前核对，写入后回查。
- 必须明确选择拼团；接口调研和核对只通过命令行完成，不操作浏览器。
- 网页没有单独的订单详情接口，列表已包含完整订单对象，所以未实现 `order-get`。查单用 `orders --query`。

## 关键决策

| 问题 | 决策与依据 |
| --- | --- |
| 时间范围 | 实测后台只按日期过滤，CLI 只接受 `YYYY-MM-DD`，按北京时间整天发送。默认近 180 天，与网页一致。 |
| “全部”状态 | 后台 0 不含已取消订单，保持与网页一致；另加 `any`，合并 0 和 100 两次查询。 |
| 翻页一致性 | 按时间升序排序，新订单只会追加到末尾；每页和结束后都核对 `total`，有变化就报错，不静默去重。 |
| 每页大小 | 实测上限为 30。 |
| 商品截断 | 网页对超过 10 种商品的订单显示“还有 N 种商品”；商品不足时调用 `/order/item/batch` 补齐。 |
| 导出粒度 | 对账默认每单一行，`--level item` 输出每个商品一行。 |
| 个人信息 | 默认 `mask`；昵称和备注保留，供二维码收款对账；`--pii full` 需要显式指定。 |
| 金额合计 | 摘要中不计入已取消订单，避免对账时虚增金额。 |
| 文件 | 0600 权限、原子替换、默认拒绝覆盖，并在查询前先检查目标文件。 |

## 实现

- `orders.py`：负责翻页与核对、补齐商品、脱敏、CSV 输出、摘要和命令执行。
- `pintuanya.py`：只注册子命令并分派，复用 `Client.request`、拼团解析、登录失效时退出码 2 和 Cookie 持久化等现有机制。
- `test_orders.py`：24 项离线测试，覆盖以下方面：
  - 日期范围和请求体；
  - 翻页及结束后复核；
  - 总数变化、重复或缺失 ID、提前出现空页、格式变化；
  - 商品补齐及补齐失败；
  - 脱敏规则，且不修改原对象；
  - 两种 CSV 粒度和空订单；
  - 未知状态和零值；
  - 摘要中排除已取消订单；
  - BOM、0600 权限、拒绝覆盖、失败不残留文件；
  - 查询前检查导出目标。
