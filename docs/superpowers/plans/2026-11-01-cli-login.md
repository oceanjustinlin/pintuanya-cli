# CLI Login Implementation Plan

**Goal:** 用 `.env` 统一凭据，提供 CLI 微信扫码登录、脱敏诊断和服务器 Cookie 更新保存。

**Architecture:** `auth_config.py` 管理配置解析和原子保存；`login.py` 管理微信协议和受限 HTTP 会话；`auth.py` 改为命令入口服务；`pintuanya.py` 接入参数与会话更新；`http_transport.py` 补充原始状态和响应头。

**Tech Stack:** Python 标准库、系统 curl、unittest。当前会话逐项实施，不并行修改共享文件。

## 任务 1：配置

- [x] 在 `test_auth_config.py` 编写解析、优先级、凭据不混用、符号链接拒绝、保存权限与冲突测试；执行 `python3 -m unittest test_auth_config -q`，确认新能力缺失。
- [x] 实现 `AuthConfig(path, environ)`，`load()`、`save(cookie, device_id)`；使用不执行 shell 的解析、0600 同目录临时文件和文件锁配合快照检查；再次运行测试。
- [x] CLI 全局增加 `--env-file` / `--no-env-file`，默认脚本目录 `.env`；参数默认值读取前加载。现有测试隔离本地配置，禁止读取真实凭据。

## 任务 2：扫码协议与传输

- [x] 在 `test_login.py` 写二维码路径提取、回调 URL 限制、轮询状态解析及模拟完整登录测试；先运行确认失败。
- [x] `login.py` 使用 CookieJar 保持上下文，HTTP 跳转显式校验，不向微信发送店铺凭据；解析数据不使用 eval。二维码 PNG/JPEG 写 0600 文件，等待/扫码/取消/过期/超时明确区分。
- [x] `http_transport.raw_request` 支持状态、重复响应头和二进制内容；敏感 URL 和头通过 stdin 传给 curl，网络失败只报告退出码。新增对应脱敏与 401 测试。
- [x] 扫码确认后回调、只读验证再保存；失败或中断保留旧配置；在 `--no-env-file` 下拒绝保存式登录。
